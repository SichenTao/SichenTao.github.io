## 1. 产品结论

v2.0 将现有个人主页、学术资料、学术前沿、AI Builder 阅读、YouTube 学习和 JSPS 科研资助信息整理为一个可理解、可维护、可扩展的网页产品家族。各产品继续保留已经高度设计的 Apple 式极简视觉：浅灰画布、留白、克制阴影、清晰大标题、胶囊控件和院校主题。v2.0 的设计工作集中在信息架构、跨站导航、组件复用、状态完整性、可访问性和账户平台接入。

这一产品家族只有一个顶层入口，但包含多种用户目的。入口负责帮助用户选择工作区；每个工作区负责完成一类清楚的任务；共享设计系统负责让相同操作在不同工作区中保持同义、同感和同样可靠。

## 3. 产品定位

### 3.1 一句话定位

面向研究者、合作者、学生和科研申请者的个人知识与工作入口，以统一的极简界面连接可信履历、学术阅读、行业跟踪、视频学习和科研资助决策。

### 3.2 核心用户

| 用户                | 首要问题                                       | 产品提供的答案                                                   |
| ------------------- | ---------------------------------------------- | ---------------------------------------------------------------- |
| 合作者与招聘方      | 陶思晨是谁、研究什么、产出与服务记录如何       | Personal Homepage 的研究档案、论文、项目、履历与外部身份         |
| 研究者与学生        | 某一学术方向有哪些代表论文、团队与期刊指标     | Academic Frontier 的论文库、主题概览、论文详情与指标账本         |
| AI 产品与研究关注者 | 值得持续关注的人和内容是什么                   | Follow Builders 的来源聚合、检索、阅读和原始链接                 |
| 视频学习者          | 如何把长视频转换为可搜索、可跳转、可复习的材料 | YouTube Learner 的文章、逐字稿、视频同步与导出入口               |
| 科研资助申请者      | 当前有哪些 JSPS 项目、截止期、表格和申请说明   | JSPS 工作台的项目筛选、时间线、材料目录与指南                    |
| 已注册成员          | 如何登录、确认权限与管理订阅                   | Account & Billing 的身份、权益、Checkout 与 Customer Portal 入口 |

### 3.3 产品价值顺序

1. **可信**：内容可追溯到公开资料或权威来源，更新时间和过期状态可见。
2. **快速**：用户从入口到目标内容不超过一次工作区选择和一次任务选择。
3. **连续**：语言、主题、筛选条件和阅读上下文在跳转与刷新后尽量保持。
4. **可复用**：相同功能由共享令牌、组件和产品模式实现，减少体验漂移。
5. **可扩展**：账户、权限、学习状态和支付内核可以服务未来网站。

## 4. 三层信息架构

### 4.1 第一层：产品家族

第一层回答“我要进入哪个工作区”。门户（Portal）展示五个内容工作区，并在全局导航中提供账户与付费入口：

```text
Portal /
├── Personal Homepage /academic-homepage/
├── Academic Frontier /academic-frontier/
├── Follow Builders /follow-builders/
├── YouTube Learner /youtube-to-ebook/
├── JSPS KAKENHI /jsps-kakenhi/
└── Account & Billing /account/
```

全局顶部导航在产品之间保持同一顺序、同一图标语义和当前页标识。账户页设置为 `noindex,nofollow`，它是用户任务入口，不进入公开内容索引。

### 4.2 第二层：工作区任务

第二层回答“在这个工作区完成什么”。每个工作区使用最少的一级任务：

| 工作区            | 主要任务模式                            | 主要路由                                                                              |
| ----------------- | --------------------------------------- | ------------------------------------------------------------------------------------- |
| Portal            | 认识产品、选择入口                      | `/`                                                                                   |
| Personal Homepage | 浏览研究档案、筛论文、确认身份          | `/academic-homepage/` 及 8 个专题页                                                   |
| Academic Frontier | 看最新、理解领域、查论文、核指标        | `/academic-frontier/`、`overview.html`、`papers.html`、`metrics.html`、`paper/*.html` |
| Follow Builders   | 搜索聚合内容、阅读长文、返回原始来源    | `/follow-builders/` 的 feed 与文章状态                                                |
| YouTube Learner   | 搜索学习材料、切换文章/逐字稿、同步视频 | `/youtube-to-ebook/` 的 library 与 reader 状态                                        |
| JSPS KAKENHI      | 找项目、看期限、取材料、读指南          | `/jsps-kakenhi/`、`program.html`、`deadlines.html`、`forms.html`、`guides.html`       |
| Account & Billing | 登录、看权益、购买、管理订阅            | `/account/`                                                                           |

### 4.3 第三层：组件、内容与状态

第三层回答“当前模块是什么、发生了什么、下一步能做什么”。它由以下共享模式组成：

- 站点外壳：品牌、跨产品导航、语言、主题、移动菜单、跳过导航；
- 筛选数据账本：搜索、筛选、排序、结果数、URL 状态、重置与空结果；
- 资源卡：标题、来源、日期、标签、摘要和主要动作；
- 长文阅读器：正文、目录或来源侧栏、段落锚点与返回上下文；
- 异步边界：加载、空、错误、过期、权限限制和可用内容互斥显示；
- 权限门：匿名、免费、付费、受阻与检查中；
- 数据新鲜度：来源、最近成功核验时间、fresh、stale 或 unknown。

## 6. 关键用户旅程

### 6.1 核对研究身份

```text
Portal → Personal Homepage → Research / Publications / Profiles → 权威外部链接
```

成功条件：用户能够从研究方向进入论文或身份来源，并始终知道自己所在的工作区和页面。

### 6.2 发现并阅读论文

```text
Portal → Academic Frontier → 搜索或筛选 → 论文详情 → DOI / 原文 / 引用复制
```

成功条件：筛选条件在 URL 中可恢复；结果数可见；空结果可以一键清除；外部来源有明确标识。

### 6.3 把视频变为可复习材料

```text
Portal → YouTube Learner → 选择文章 → 逐字稿模式 → 时间戳定位视频 → 保存进度/书签/笔记 → 经授权导出
```

当前公开静态阅读和视频同步已有页面实现。云端进度、书签、笔记和受限导出需要完成真实账户平台接入后验收。

### 6.4 从科研资助问题到官方材料

```text
Portal → JSPS → 筛项目 → 看项目详情 → 核截止期 → 下载或打开官方材料 → 阅读指南
```

成功条件：项目、时间线和表格互相可追溯；每条关键结论可以到达权威来源；过期数据具有可见提示。

### 6.5 从匿名访问到付费权益

```text
公开内容 → Account → 登录 → 选择已批准方案 → Stripe Checkout → Webhook 同步 → Entitlement 生效 → 返回原学习上下文
```

成功条件：客户端不会短暂展示受保护内容；重复购买请求不会产生多个购买意图；取消、失败、过期和退款均能收敛到正确权限。

## 7. 视觉设计原则

### 7.1 保持现有视觉真相

v2.0 以 v1.0 实际渲染为视觉基准，持续使用：

- `#f5f5f7` 浅灰画布和轻透明白色表面；
- Newsreader 展示字体、Sora 界面字体及中日系统字体回退；
- 大面积留白、清楚的标题层级、克制边框和低密度阴影；
- 30/34/44 px 控件体系、胶囊按钮和已有圆角；
- Tohoku 紫、Toyama 蓝灰、USST 红三套主题；
- 现有头像、机构标志、工作区标志和 29 个图标 sprite。

任何改动都要能解释为一致性、可访问性、响应式或状态完整性的改善。新增颜色、字体、图标语言、卡片造型或装饰风格需要单独的设计决策和截图证据。

### 7.2 信息密度

入口页面保持低密度，优先传达“有哪些产品”和“每个产品解决什么”。列表页面允许中密度，用筛选与元数据提高扫描速度。详情和阅读页面保持 760 px 左右的可读正文宽度，并把来源、目录或辅助信息放入侧栏。

### 7.3 视觉层级

1. 当前任务标题始终最强；
2. 主要动作使用主题强调色；
3. 次要动作保持轻表面或文字链接；
4. 来源、日期、标签和状态进入较弱层级；
5. 错误、过期和权限状态使用文字、图标与颜色的组合表达。

## 8. 交互原则

### 8.1 方向感

每页只有一个 `<main>`，顶部导航使用 `aria-current` 标记当前位置。移动端导航折叠后仍保留完整产品集合，Escape 关闭临时面板并把焦点还给触发器。

### 8.2 连续性

主题使用 `sichen-homepage-theme`，语言使用共享存储键，并在产品路由允许时同步 URL。搜索、筛选和排序状态应写入 URL；从详情返回列表时恢复之前的查询和位置。

### 8.3 一次只显示一个状态

依赖数据或权限的模块使用单一 `data-state`。错误、权限检查、权限拒绝、加载、空、过期和可用内容按既定优先级解析，避免内容、加载图标和错误同时出现。

### 8.4 可恢复错误

错误文案说明三件事：发生了什么、用户输入或数据是否保留、下一步能做什么。网络失败不得清空搜索；支付取消返回原上下文；登录过期提供重新登录入口。

## 9. 语言、主题与状态系统

### 9.1 语言

全局界面支持英语、简体中文和日文。切换语言后，按钮名称、可访问名称、状态文案、日期格式和页面元数据需要同步变化。Academic Frontier 使用独立语言路由；其他工作区主要使用客户端本地化。缺少翻译时展示明确的原始语言内容，不能把机器翻译伪装为人工审校。

### 9.2 主题

默认主题为 Tohoku。主题只改变文字层级、强调色、辅助色和柔和表面，公共画布和主要布局保持一致。未知值与旧 `base`、`default` 值统一回退到 Tohoku。

### 9.3 状态词汇

| 状态      | 用户可见含义         | 必需动作或说明                      |
| --------- | -------------------- | ----------------------------------- |
| loading   | 正在确认或读取       | 可见文字、`aria-busy`，避免重复操作 |
| empty     | 当前条件没有结果     | 清除条件或创建第一项                |
| error     | 请求失败             | 说明保留内容并提供重试              |
| stale     | 数据仍可读但可能过期 | 显示最近核验时间和来源              |
| paywalled | 当前权益不足         | 登录、升级、恢复购买或管理订阅      |
| success   | 操作完成             | 明确下一任务                        |

## 10. 响应式与设备体验

共享断点为 380、760、820、1160、1440 和 1760 CSS px。760 px 以下进入移动导航；1160 px 以下的阅读器从双栏变为单栏。页面必须在 320 CSS px、200% 缩放以及中英日长文案下保持信息完整。

主要移动控件使用至少 44 px 高度。Header 内 30 或 34 px 的次级控件需要保留可见名称或可访问名称，并保持足够间距。响应式验收关注任务顺序、可读宽度、触控范围和焦点路径，不能只判断“页面没有溢出”。

## 11. 无障碍目标

工程目标为 Web Content Accessibility Guidelines 2.2 AA（WCAG 2.2 AA）。发布前必须完成：

1. 键盘走通导航、搜索、筛选、语言、主题、登录、结账返回、订阅管理和受保护下载；
2. VoiceOver 检查 landmark、标题层级、表单名称、结果数和异步播报；
3. 桌面 1440 × 900 与移动 390 × 844 的代表路由 axe 扫描；
4. 320 CSS px、200% 缩放、强制色与减弱动效检查；
5. 人工复核对比度、焦点可见、错误恢复、阅读负担和触控目标。

自动化零违规只说明已覆盖规则未发现问题，完整 WCAG 符合性仍需人工证据。

当前本地证据为 8 条代表路由、桌面与移动两个视口，共 16 次 axe 扫描且自动违规为 0。该结果尚未替代上述键盘、VoiceOver、缩放、强制色和触控目标人工验收。

## 12. 内容可信度与新鲜度

`content/freshness.json` 只在实际访问声明来源、通过 schema、确认差异后更新。独立 policy 规定：Academic Frontier 最长 45 天且至少 15 条；Follow Builders 最长 7 天；JSPS 最长 7 天；学习目录最长 30 天且至少 2 条。

当前 Follow Builders 与 JSPS 已通过 freshness。Academic Frontier 保留 2026-05-08 的 15 篇公开论文；候选的 8 篇更新会删除 14 篇现有记录，且缺少审核链，因此继续 **FAIL**。YouTube Learner 保留 2026-05-15 的 2 篇文章；站点专用导入器尚未建立，因此继续 **FAIL**。全局 freshness 门禁当前为 **BLOCKED 2**。

## 13. 账号与付费体验原则

### 13.1 身份

一个 Supabase Auth 用户可以加入多个 `applications`。邮箱 Magic Link、Google 和 GitHub 是当前账户页展示的登录方式。生产启用前要配置允许的重定向 URL、身份提供商、邮件模板、会话过期和账户恢复策略。

### 13.2 商业方案

页面可以展示方案结构，但价格、币种、周期、试用、税务、退款和最终方案键以经产品负责人批准的 Stripe Product/Price 和 `plans` 记录为准。未配置 `provider_price_id` 的付费方案保持停用。

### 13.3 权益

前端读取 `entitlements` 形成展示，服务端在数据库行级安全、私有存储和签名 URL 端点再次授权。购买成功页面本身不授予权限；Stripe 签名 Webhook 完成订阅与权限同步后才产生有效权益。

### 13.4 隐私

平台只保存提供服务所需的身份、同意、账单映射、权益与学习状态。支付载荷账本保存事件类型、哈希和处理状态，不保存完整 Stripe Payload。正式上线前需要确认隐私政策版本、数据保留、账号删除、未成年人、版权和法域要求。

## 14. 非目标

- v2.0 不改变陶思晨个人品牌、核心视觉语言或既有内容定位；
- v2.0 不把 Quant Platform 发布到 GitHub Pages，也不让它复用学习平台密钥、数据库或用户令牌；
- v2.0 不在未批准价格、税务和退款政策前启用 Live Mode；
- v2.0 不把自动翻译视为人工审校内容；
- v2.0 不以一次组件封装宣称所有旧页面已经完成迁移；
- v2.0 不以自动化扫描代替最终视觉、键盘、屏幕阅读器和真实支付验收。

## 16. v2.0 产品验收定义

v2.0 只有在以下四类证据同时成立时进入发布候选：

1. **内容体验**：全部主要路由、深链接、语言、主题、搜索、筛选、阅读和恢复动作通过；
2. **视觉体验**：基线与实现使用相同视口、相同状态并排比较，`design-qa.md` 标记 Passed；
3. **平台体验**：真实 Supabase/Stripe 测试环境完成登录、Checkout、Webhook、Portal、权益和受限资产闭环；
4. **发布体验**：内容时效、构建、链接、安全、无障碍、部署后 smoke 和回滚演练均有可追溯记录。

在外部账户平台尚未激活时，静态产品家族可以作为 v2.0 Preview 交付；付费能力需要保留“尚未配置”的清楚状态，并避免展示可执行但必然失败的购买入口。
