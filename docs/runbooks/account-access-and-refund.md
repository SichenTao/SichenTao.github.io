# 账号访问纠错与退款

## 身份核验

支持操作以已登录账号、受控邮箱验证或支付提供方客户映射为依据。不得要求用户发送密码、完整支付卡号、访问令牌或身份证件到普通 issue。

## 权益纠错

1. 确认应用、用户、订阅、权益功能和当前时间范围。
2. 比较 Stripe 当前对象、本地 webhook ledger 与 entitlement 投影，识别延迟、映射错误或产品配置错误。
3. 使用可审计的管理函数执行纠正，记录理由、依据、旧值、新值和操作人；前端 localStorage 变化不构成修复。
4. 让用户重新建立会话并验证目标内容；同时确认其他应用和 Quant 隔离边界未受影响。

## 退款

退款必须遵循发布时生效的价格、退款与服务条款。Stripe 退款对象是金额事实；本地系统在 webhook 确认后更新订阅和权益。部分退款、争议款和取消续订分别记录，避免把“取消未来续订”误处理为“立即退款并删除既有记录”。

关闭工单前保存用户确认、Stripe 对象 ID、审计事件 ID、完成时间和仍适用的访问截止时间。数据删除请求进入独立隐私流程，保留法律或财务必须保存的最小记录。
